9AM UI is the UI layer every 9AM Studios script is built on. It is distributed as a
**[shadcn registry](https://ui.shadcn.com/docs/registry)**: components are
copied into each script rather than imported from a package, so a script can diverge
when it genuinely needs to — while [`9am-ui check`](/docs/drift-policy) makes sure
nobody diverges by accident.

It was extracted from `9am-vehicleshop` v1.2.8, which is consumer #0.

## Why a registry and not a package

A FiveM script ships as a folder on someone else's server. There is no install
step a customer runs, no lockfile to resolve, and — for escrowed builds — no
practical way to patch a dependency after the fact. A package would mean every
script carrying a version of the kit it can never update in place.

Copying the source in instead means each script owns its UI outright. The cost
is drift, and drift is what the [drift policy](/docs/drift-policy) and
`9am-ui check` exist to bound: the theme is locked and fails CI if it changes,
components warn but are allowed to diverge, and `nui.config.ts` is expected to.

## The two pieces that matter most

[`@9am/viewport`](/docs/components/viewport) is the house scroll container: a
draggable custom scrollbar, layered liquid-glass edge blur, and a header that
blur-swaps to a sticky copy as you scroll. It also carries the CEF-103
workarounds — `clipPath` instead of `overflow` plus radius, stacked fixed-blur
bands because `mask` does not apply to `backdrop-filter` output, and
JS-computed grid columns because `:has()` and `@container` do not exist in
Chromium 103.

[`@9am/smooth-scroll`](/docs/lib/smooth-scroll) exists because CEF will not
wheel-scroll a `clip-path`'d container at all. Without it the viewport is
unscrollable in game while working perfectly in your browser.
